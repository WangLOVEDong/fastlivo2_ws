# FAST-LIVO2 Avia 学习导航

这份导航配合源码阅读。每次先理解一个模块的数学目标，再看其参数、成员变量和少量代码。
硬件路线为 Livox Avia、Livox IMU、MVS 相机；其他雷达适配已从学习版移除。

## 1. 从这里开始

先读 `src/main.cpp`，随后在 `src/LIVMapper.cpp` 中查找 `LIVMapper::run()`。

```text
传感器回调入队
    ↓
sync_packages(LidarMeasures)
    ↓
processImu()：预测状态、去畸变，保存 state_propagat
    ↓
stateEstimationAndMapping()
    ├─ LIO/LO → handleLIO() → 点面更新、地图维护
    └─ VIO    → handleVIO() → 光度更新、图像/彩色点云输出
```

这是同一主循环按事件进行分发。在 LIVO 模式，一个图像时刻先产生 LIO 事件，
下一次同步再产生同一时刻的 VIO 事件；不是每轮都重新积分一遍相同 IMU。

| `src/LIVMapper_sync.cpp` | Livox/IMU/图像回调及 `sync_packages()` |

| `src/preprocess.cpp` | Avia 点的抽取、盲区过滤、逐点时间 |

## 3. 主函数的参数与输出

| 函数 | 参数或成员输入 | 输出 |
|---|---|---|
| `LIVMapper(nh)` | `nh`：读取 ROS 参数 | 创建处理模块、连接共享状态 |
| `run()` | 无显式参数，使用传感器缓存 | 持续调度同步/预测/更新 |
| `Preprocess::process(msg, pcl_out)` | `msg`：Livox 帧；`pcl_out`：输出指针 | LiDAR 系点，`curvature` 保存相对时间(ms) |
| `sync_packages(meas)` | `meas`：同步包引用；内部读取各传感器缓存 | 返回是否产生事件，并填写点云/IMU/图像/时间 |
| `processImu()` | 成员 `LidarMeasures`、`_state` | 预测状态、`feats_undistort`、`state_propagat` |
| `Process2(lidar_meas, stat, cur_pcl_un_)` | 同步包、输入/输出状态、输出点云指针 | IMU 初始化或传播与去畸变 |
| `handleLIO()` | 当前点、先验状态、已有地图 | 后验 `_state`、更新地图及 `_pv_list` |
| `StateEstimation(state_propagat)` | IMU 先验；点云和地图通过成员传入 | `VoxelMapManager::state_` 保存后验 |
| `BuildResidualListOMP(pv_list, ptpl_list)` | 带不确定性的当前点、输出点面列表 | 有效的 `PointToPlane` 约束 |
| `UpdateVoxelMap(input_points)` | 校正后的世界点与协方差 | 融合/细分体素平面 |
| `handleVIO()` | 当前图像、`_pv_list`、体素地图 | 通过视觉模块修正共享 `_state` |
| `processFrame(img, pg, feat_map, img_time)` | 图像、LIO 点、地图、相对时间(s) | 更新状态、视觉点及参考 patch |
| `updateState(img, level)` | 当前灰度图、金字塔层级 | 光度迭代更新共享状态和协方差 |

## 4. 核心变量速查

| 变量 | 定义/用途 |
|---|---|
| `p_pre` | Livox 点云预处理器 |
| `p_imu` | IMU 初始化、状态传播和去畸变处理器 |
| `voxelmap_manager` | 体素平面地图及点面状态更新 |
| `vio_manager` | 视觉地图和光度更新，`state` 指针指向 `_state` |
| `_state` | 当前名义状态，预测和两种更新都会改变它 |
| `state_propagat` | IMU 预测先验，迭代求解的参考状态 |
| `LidarMeasures` | 当前同步测量包及 LIO/VIO 事件标志 |
| `feats_undistort` | 去畸变后点云，仍为 LiDAR 系 |
| `feats_down_body` | 降采样后 LiDAR 系点云；body 这个名字不表示已经转到 IMU 系 |
| `feats_down_world` | 当前位姿下的世界系点云 |
| `_pv_list` | 当前点坐标及不确定性，不是单纯的平面列表 |
| `ptpl_list_` | 每个有效点与匹配平面的对应关系 |
| `extR/extT` | LiDAR→IMU 外参，`p_i = extR*p_l + extT` |
| `Rcl/Pcl` | LiDAR→相机外参，`p_c = Rcl*p_l + Pcl` |

`StatesGroup` 的19维误差顺序：

```text
姿态[0:3]  位置[3:6]  逆曝光[6]  速度[7:10]
陀螺零偏[10:13]  加速度零偏[13:16]  重力[16:19]
```

区间采用左闭右开。`rot_end/pos_end` 表示当前更新时刻状态；LIVO 中该时刻可为图像时刻，
未必是一个完整 LiDAR 扫描的最后时刻。

## 5. 先复习 LIO 的数学主线

点的世界坐标：`p_w = R_wi * (R_il*p_l + t_il) + p_wi`。
`p_l` 为雷达点，`R_il/t_il` 为外参，`R_wi/p_wi` 为 IMU 世界位姿。

点面残差：`r = nᵀ(p_w-q)`。
`n` 为世界系单位法向量，`q` 为平面中心，`r` 是有符号距离(m)。

`Hsub` 是 N×6 雅可比，前三列旋转、后三列位置；`meas_vec=-r`。
`R_inv` 只存 N 个残差方差倒数，相当于对角权重矩阵的对角线。
原始点协方差和平面参数协方差先投影到同一个标量残差空间，再按模型近似相加。

`solution` 是19维状态修正量；注入时姿态右乘 `Exp(δθ)`，位置加 `δp`。
`rematch_num` 在此实现中用于停止判断，点面匹配实际每轮都会重新计算。
后验协方差在停止时更新，随后用校正后的世界点更新地图。

学习检查点：能把 `pv_list_ → ptpl_list_ → Hsub/R_inv/meas_vec → solution → state_` 串起来。

## 6. 再进入视觉

按以下顺序查找 `vio.cpp` 中的函数：

1. `processFrame(img, pg, feat_map, img_time)`：一帧视觉处理的总入口。
2. `retrieveFromVisualSparseMap(img, pg, plane_map)`：筛选可见地图点和参考 patch。
3. `computeJacobianAndUpdateEKF(img)`：由粗到细处理金字塔。
4. `updateState(img, level)`：默认前向光度更新；先理解残差再读雅可比。
5. `generateVisualMapPoints(img, pg)`：补充有纹理的新三维点。

`img` 为当前图像，`pg` 为 LIO 点，`plane_map/feat_map` 为体素地图；
`level` 为金字塔层级，`img_time` 为相对时间。光度残差比较参考 patch 与当前 patch 的亮度，
曝光状态用于模型中的亮度补偿。逆组合、光线投射、COLMAP 和绘图均保留，第一遍可跳过。
